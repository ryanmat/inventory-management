Factory Inventory Management System

Architecture overview — Vue 3 SPA over a FastAPI mock-data backend. No database; all state is in-memory, loaded from JSON at startup.

System Architecture

Frontend Vite dev server :3000

  • Vue 3 SPA — Composition API
  • 6 routed views (Dashboard, Inventory, Orders, Demand, Spending, Reports)
  • 9 components (modals, FilterBar, profile, language switcher)
  • 3 composables (useFilters, useAuth, useI18n en/ja)
  • api.js — single axios client
HTTP / JSON
axios, CORS open
filters as query params

Backend FastAPI :8001

  • main.py — 14 GET endpoints, 309 lines
  • Pydantic v2 response models
  • Shared filter helpers (warehouse / category / status / month+quarter)
  • Aggregation in Python (dashboard summary, quarterly reports)
import-time load
mock_data.py
←

Data in-memory

  • 7 JSON files in server/data/
  • inventory, orders, demand, backlog, spending, transactions, purchase orders
  • Sept-2025 sample dataset
  • Regenerated by generate_data.py
  • No persistence — restarts reset state

Both processes are started together by scripts/start.sh. CORS allows all origins; the client hardcodes http://localhost:8001/api (no Vite proxy).

Data Flow

Read path (every view)
FilterBar selections→ useFilters shared refs→ view watch triggers reload→ api.js builds query params→ FastAPI apply_filters / filter_by_month→ Pydantic model validation→ refs updated→ computed props render SVG charts
Startup path
server/data/*.json→ mock_data.py loads at import→ module-level Python lists→ endpoints filter per request

Filtering is server-side only; the client re-fetches on every filter change rather than filtering locally. Inventory has no time dimension, so the month filter does not apply to it.

Observed Gaps

Client/server API mismatch

The backend is entirely read-only (14 GET routes, zero POST/PATCH/DELETE), but client/src/api.js defines write operations with no server counterpart:
  • Tasks CRUD — App.vue calls getTasks() on load and logs a 404 to the console on every page view.
  • Purchase orders — create/read calls exist client-side; mock_data.py even loads purchase_orders.json, but no route exposes it.
